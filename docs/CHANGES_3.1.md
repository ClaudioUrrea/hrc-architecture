# Release 3.1: changes and the review point each one answers

Release 3.0 (tags `campaign-v3`, `campaign-v3-compare` and `campaign-v3-report`, Figshare
10.6084/m9.figshare.34845711) is the version evaluated in the round-3 manuscript. It is kept
unchanged. Release 3.1 corrects the defects that Reviewer 2 identified in round 4. All its
campaigns are run again, from a configuration that is frozen and published before the first run.

| # | Round-4 point | Change | Where | Validation |
|---|---|---|---|---|
| 1 | Speed scaling after the barrier QP can violate a row | The supervisor scale and the SSM limit are applied **inside** the QP. The box and the nominal command become `sigma*qd_max` and `sigma*qd_nom`. When the SSM limit binds, `sigma` is backed off and the QP is re-solved; the solution is never scaled afterwards. If the rows cannot be met within the speed limits, the robot stops (`kFlagLimitConflict`). A final check compares the dispatched command with every row, the box and the SSM limit; any violation turns the command into a stop (`kFlagFinalCheckFailed`), and the residual is logged every cycle (`final_viol`). | `src/safety/limited_filter.cpp` (`limited_filter`, `command_violation`); `apps/hrc_run.cpp` (safety strategy) | `tests/test_r31.cpp`: the reviewer's numerical example; explicit conflict; 20 000 random problems with zero violations in 3.1 (the 3.0 composition violates rows in the same problems) |
| 2 | Supervisor priority removes restrictions | The reported mode is still the most severe active condition. The limits are now composed over all active conditions: speed scale = minimum, floor = maximum, and the learned barrier is suspended if a fallback or degraded stream is active. The active conditions are logged every cycle (`cond_mask`). A floor raised in a cycle now applies in that same cycle (`GeometricCbf::retighten`). | `src/control/supervisor.cpp` (`Supervisor::update`), `include/hrc/supervisor.hpp` | `tests/test_r31.cpp`: low confidence + overrun (0.7 / 0.225 m kept); overrun does not lift the geometric fallback; all pairs of conditions and their clearing transitions; stop clears to the remaining condition |
| 3 | `SeqlockSlot` data race | The payload is copied word by word with `std::atomic<uint64_t>` relaxed operations, bracketed by the sequence counter and fences (Boehm 2012), so there is no unsynchronised access. The lunge injector no longer reads the control thread's kinematics. | `include/hrc/spsc.hpp`; `apps/hrc_run.cpp` (`tg.lunge`) | concurrent stress tests (`r31_seqlock_*`, `r31_spsc_*`); full ThreadSanitizer build with no reports; limits of that check stated in `docs/BUILD.md` |
| 4 | Cartesian stopping from a joint-space stop | Offline check of the stop at 3 rad/s² with reaction delay `T_r` against Eq. (3), for every sampled link point, at the configurations and commanded speeds logged in the campaigns | `tools/stop_check.cpp`, `tools/stop_samples.py` | output reported in the paper |
| 5 | Floor crossings: estimate vs ground truth | New per-cycle fields: ground-truth separation (`gt_min_sep_m`), estimate error (`est_err_max_m`, `est_err_closest_m`, matched to the estimate by its publication number), SSM limit (`v_ssm_ok`), measured joint speed (`qd_meas_norm`, which separates deceleration from standstill). The pilot showed that the simulated estimate error is much larger than `Z_d` = 0.04 m and that the barrier had no position-uncertainty term. Therefore a position margin is added to the barrier (`control.position_margin`), and it and `Z_d` are calibrated by a rule fixed before the calibration runs | `include/hrc/records.hpp`, `apps/hrc_run.cpp` (ground-truth probe), `src/safety/geometric_cbf.cpp`, `tools/calibrate_position_margin.py`, `analysis/behaviour.py` | `docs/PREREGISTRATION_3.1.md` §2 |
| 6 | Availability definition | Three time-weighted metrics: outside stop modes, motion permitted (which includes controller-level stops) and mean speed scale (a proxy). Unrecorded intervals are reported. Controller-level stops are logged as events | `analysis/faults.py` | — |
| 7 | Detection credited twice; recovery attributed to another fault | One-to-one matching (a detection is reserved). Overlapping, ambiguous and absorbed injections are reported explicitly. An episode of a category is the maximal period with at least one condition of that category active. Recovery runs to the end of that episode; a non-interrupting event has recovery 0 | `analysis/faults.py` | applied to the 3.0 injection records: configuration inconsistency now has recovery 0 (3.0: 78 s median) |
| 8 | Weibull KS and Poisson intervals | The Weibull fit is descriptive, with a parametric-bootstrap goodness of fit that reproduces cold starts and censoring. Rates get a run-level bootstrap interval and a dispersion index in addition to the exact Poisson interval | `analysis/stats.py`, `analysis/faults.py` | — |
| 11 | Equivalence; PF without the SSM limit | No equivalence claim and no margin. A new baseline, `pf_ssm`, is the potential field under the same SSM limit, tuned and compared like the others (8 Holm-adjusted tests). The minimum true separation is a secondary endpoint | `include/hrc/control.hpp`, `apps/hrc_run.cpp`, `tools/make_campaigns.py`, `analysis/baselines.py` | — |
| 12 | "Pre-registered" | 3.0 is described as pre-specified. For 3.1, the code, the calibration rule, the design and the analysis are published at tag `r31-calibration` before any run; the frozen configuration (`campaign-v4`) and the comparison configuration (`campaign-v4-compare`) are published, with server-timestamped records, before the runs that use them | `docs/PREREGISTRATION_3.1.md`, `docs/freeze/` | GitHub timestamps |
| 13 | Endpoint of the execution time | Execution time runs from wake-up to completion of the enqueue of the cycle record. The enqueue is measured and logged in the next record (`d_enqueue_prev_ns`). Deadline misses, the supervisor's overrun input and the run summary use that endpoint | `apps/hrc_run.cpp` (end of cycle), `analysis/hrc_logs.py` (`exec_ms`, `deadline_miss`) | — |
| R | `-O3` in the text; missing scripts | Actual build commands and flags are documented. The four manuscript scripts are added unchanged, with the full route from raw records to results, macros and figures | `docs/BUILD.md`, `paper/r3_reproduction/` | SHA-256 of each script in its README |

The cycle record grows from 192 to 208 bytes. Each run's `schema.json` describes it, and
`analysis/hrc_logs.py` reads records from both 3.0 and 3.1 runs.
